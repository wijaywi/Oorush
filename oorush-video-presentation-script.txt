OORUSH VIDEO PRESENTATION SCRIPT
================================

Language: English
Target runtime: 2 minutes 30 seconds
Format: 16:9, 1080p, clean technical product presentation
Audience: Developers, blockchain researchers, security-minded builders, and judges

CORE MESSAGE
------------

Oorush is an educational, reproducible blockchain MVP that combines a UTXO
transaction model, proof-of-authority validation, and post-quantum Dilithium5
signatures in a small Rust codebase.

VALUE-ADDED PROMISE
-------------------

Do not present Oorush as “another blockchain.” Present the two discoveries that
make it memorable:

1. POST-QUANTUM PROTECTION — Dilithium5 gives the project a concrete migration
   path for transaction authenticity beyond classical public-key assumptions.
   Value: viewers can see the complete Sign -> Verify -> Commit flow in a small,
   inspectable implementation rather than trusting a black-box claim.

2. PIANO MELODY IDENTITY — each public key or address deterministically produces
   a short piano melody. The same input always produces the same WAV output.
   Value: an abstract cryptographic identity becomes recognizable, demonstrable,
   and easy to remember without exposing a private key or adding a secret.

THE ONE-LINE DIFFERENTIATOR
---------------------------

Oorush protects identity for the future and gives that identity a sound people
can recognize today.

Present Oorush as a transparent research and education project, not as a
production-ready public blockchain. The current implementation is a local
proof-of-authority network and does not provide Byzantine fault tolerance,
fork choice, finality, peer discovery, transport security, or production
authentication.

FULL VOICE-OVER SCRIPT
----------------------

What if blockchain identity could be protected for the future and recognized by
people today? Meet Oorush: a small, reproducible blockchain with two
distinctive ideas — post-quantum signatures and a piano melody for every public
address.

Blockchain systems can be difficult to understand, reproduce, and verify.
Oorush turns that complexity into visible proof: a compact Rust implementation,
repeatable tests, and a result you can not only inspect, but hear.

At its core, Oorush is an educational UTXO blockchain. Wallets create signed
transactions, a validator assembles valid transactions into blocks, and the
chain state tracks unspent outputs. Developers can follow the complete flow
from key to transaction to committed block.

Every transaction is signed with Dilithium5, a post-quantum signature scheme.
The added value is visible, not theoretical: the node verifies the signature,
checks ownership and inputs, and rejects invalid or conflicting transactions.
Sign, verify, commit — in one inspectable path.

Here is the feature people remember. Give Oorush a public key or address and it
deterministically composes a short piano melody. The same input produces the
same audio every time. It does not replace cryptographic verification; it adds
a human-facing identity layer that makes a key easier to demonstrate, compare,
and remember.

The wallet is generated locally and stored in encrypted form. Password input is
handled interactively, while private keys remain inside the wallet and signing
flow — never in the dashboard or network status API.

Oorush uses proof of authority for its local network. A configured validator
signs a block, the node validates the structure and signature, and the state is
persisted. Developers can inspect this process through a small line-oriented
JSON protocol with explicit commands and structured responses.

A read-only status API and validator dashboard show public chain and validator
metadata without accepting private keys or signing commands. The audience can
see the protected identity, then hear the same identity as a melody, without
exposing secrets.

The project is built for reproducibility: the Rust toolchain is pinned,
dependencies are locked, Docker support is included, and the test suite can run
offline. Anyone can reproduce the transaction checks and deterministic audio
output instead of taking the demo on faith.

Oorush is an educational MVP, not a production public blockchain. Its value is
the combination: future-facing signature research plus a memorable way to
experience cryptographic identity. Explore the code, run the tests, hear the
result, and build on what you can verify.

PRODUCTION NOTES AND ACCURACY GUARDRAILS
----------------------------------------

- Describe Oorush as an educational blockchain MVP or local research network.
- Say “post-quantum signature scheme” rather than claiming that the entire
  system is quantum-proof.
- Explain the added value explicitly: Dilithium5 protects transaction
  authenticity, while the piano melody makes a public identity recognizable.
- Say that the melody is deterministic and human-facing, not a replacement for
  signature verification and not a security control.
- Say “proof of authority” rather than “mining”; the oorush-miner binary is a
  validator dashboard and does not perform proof-of-work mining.
- Do not show or narrate passwords, private keys, or unredacted wallet files.
- Do not imply that the current MVP provides public-network consensus,
  Byzantine fault tolerance, finality, fork choice, peer discovery, transport
  security, or production authentication.
- Keep the dashboard described as read-only and observational.
